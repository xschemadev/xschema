## Codebase Patterns

### Shared Cache Architecture (US-001)
- `fetcher.SharedCache` is the single source of truth for all fetched schemas
- Create cache in `generate.go`, pass to `retriever.Options.Cache` and `processor.Options.Cache`
- `metaschema.GetWithCache()` accepts cache parameter for deduplication
- Cache normalizes URIs internally (strips fragments)
- Thread-safe via `sync.RWMutex`

- Implementation was already correct: URI decode first, then JSON pointer unescape (~1→/, ~0→~)
- Files changed:
  - cli/bundler/bundler_test.go - added edge case tests for RFC 6901 compliance
- **Learnings for future iterations:**
  - RFC 6901 §6: when JSON pointer is in URI fragment, percent-decode first, then apply tilde unescaping
  - For key "literal~1key", encode as `~01` (escape the tilde)
  - For key "uri%2Fslash" (literal percent-2-F), encode as `%252Fslash` (double-encode the percent)
  - The PRD acceptance criteria was wrong - corrected to match actual RFC 6901 spec

## 2026-01-13 - US-006
- Fixed quadratic $defs flattening to O(n) linear time
- Root cause: old algorithm iterated over ALL rewrites for each def, causing O(n²) behavior
- New algorithm:
  - `collectDefsRecursive` returns newly added rewrite keys (not iterating all)
  - Single DFS pass collects all defs and builds complete rewrite map
  - Single pass rewrites all refs after collection
- Files changed:
  - cli/bundler/bundler.go - rewrote flattenDefs, collectDefsRecursive, added rewriteRefs, lookupRewrite, stripDefs
  - cli/bundler/bundler_test.go - added TestBundle5LevelNestedDefs, BenchmarkFlattenDefs, TestFlattenDefsLinearScaling
- **Learnings for future iterations:**
  - When building rewrite maps recursively, track newly added keys per call instead of iterating entire map
  - Linear scaling test: compare ratio of time(depth=10)/time(depth=5) - should be ~2 (linear), not ~4 (quadratic)
  - lookupRewrite uses longest prefix match for refs with sub-paths (e.g., #/$defs/X/properties/foo)
