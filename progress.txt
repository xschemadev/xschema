## Codebase Patterns
- core parser hard-fails are discoverable via `throw new Error` / `is not supported` searches in `typescript/packages/core/src/parser/` and `typescript/packages/core/src/utils/json-pointer.ts`
- keyword behavior is split between `normalizeDeep` (legacy rewrites) and the parser; check both before assuming a keyword is "ignored"
- workspace packages resolve `@xschemadev/core` via built `dist`, so run `bun run build` after core api/type changes
- composition parsing: if `allOf`/`anyOf`/`oneOf` is present, `hasBaseSchema` must include object/array keywords (`additionalProperties`, `dependencies`, etc) or base constraints get silently dropped
- draft3 deps: `dependencies: {"bar": "foo"}` is valid; normalizer should coerce string-shorthand to `[{...}]`-style arrays before parsing

- root cause: Value.Check cannot validate Type.Unsafe schemas (oneOf, if/then/else, etc)
- added US-014 (typebox: switch validation to ajv) and renumbered subsequent stories
- Files changed: `tasks/adapters-optimization/typebox-discovery.md`, `prd.jsonc`, `progress.txt`
- **Results:**
  - baseline is 37-42% vs zod's 93-99% and valibot's 90-95%
  - ~500 tests fail with 'Unknown type' error from TypeBox's Value.Check
  - TypeBox generates valid JSON Schema via Type.Unsafe but Value.Check can't process it
- **Learnings for future iterations:**
  - TypeBox's Value.Check only validates native TypeBox type kinds (Type.String, Type.Object, etc)
  - Type.Unsafe<T>({...}) generates JSON Schema but Value.Check throws "Unknown type" for non-native constructs
  - Solution: use Ajv to validate TypeBox schemas since they ARE valid JSON Schema
  - TypeBox supports: minLength/maxLength, min/max, pattern, uniqueItems, contains, additionalProperties natively
  - TypeBox does NOT support via Value.Check: oneOf, if/then/else, dependentSchemas, propertyNames, patternProperties (as option)
  - Format validation requires FormatRegistry setup - unregistered formats cause all values to fail
