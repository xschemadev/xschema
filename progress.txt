### Remaining known limitations (impossible with static codegen)

1. **Dynamic/Recursive References** - `$dynamicRef`, `$dynamicAnchor`, `$recursiveRef`, `$recursiveAnchor`
   - requires runtime scope tracking during validation
   - bundler blocks these keywords

2. **Bundler ref resolution edge cases** - refs with relative URIs + $id combinations
   - "refs with relative uris and defs", "URN ref with nested pointer ref"
   - bundler issue, not adapter issue

3. **Metaschema validation** - validating `$defs` against the metaschema
   - requires fetching/processing official metaschemas (which contain dynamic refs)

4. **Vocabulary control** - custom metaschemas that disable validation vocabulary
   - we always apply validation keywords

5. **Draft3 type with inline schemas** - `type: ["string", {properties: {...}}]`
   - legacy feature removed in draft4+
   - already documented in zod README

### Learnings
- all remaining failures are bundler-level blocks or out-of-scope features
- zod adapter itself has no fixable bugs remaining
- the draft3 required fix also improved compliance for valibot, effect, arktype (shared core parser)

## 2026-01-11 - US-002: Runner skips known issue tests

### What was implemented
- added LoadKnownIssues() to load known-issues.json from adapter's compliance directory
- pre-filtering phase in processKeyword() identifies known issues BEFORE bundling
- groups where ALL tests are known issues are skipped entirely (no bundling, no harness)
- groups with SOME known tests still execute, but known tests are filtered out
- KnownIssues count tracked in DraftSummary struct
- CLI output shows "X known" suffix when known issues exist

### Key design decisions
- filter known issues BEFORE bundling to avoid failing tests that would error during bundle
- test path format: {draft}/{keyword}/{group_description}/{test_description}
- known issues don't affect pass/fail/skip counts, tracked separately
- percentage calculation: passed / total (excludes known issues from both)

### Files changed
- cli/compliance/runner.go (LoadKnownIssues, processKeyword pre-filtering)
- cli/compliance/types.go (added KnownIssues field to DraftSummary)
- cli/cmd/compliance.go (formatDraftResult shows known issues)
