## Task: fix-none-union-syntax (COMPLETED)

**Objective:** Fix 'None | None' type annotation error causing TypeError crashes

**Root Cause:**
- `render_union()` in renderer.py generated duplicate type expressions (e.g., "None | None")
- Python's `|` operator doesn't support `NoneType | NoneType`, causing runtime TypeError
- This crashed compliance test batches before any tests could run

**Solution:**

- Prevents invalid Python syntax like "None | None"

## Task: fix-type-keyword (COMPLETED)

**Objective:** Fix remaining type keyword failures (was 83.8%, now 100%)

**Root Causes:**
1. **Boolean/integer confusion**: Python's bool is a subclass of int, so `isinstance(True, int)` returns True. Pydantic's default `bool` type accepts 0/1 as booleans.
2. **Type coercion**: Pydantic's default types coerce strings to numbers (`"1" -> 1`) and numbers to strings (`1 -> "1"`).
3. **Object type guard bug**: `_is_object_only_schema()` was always returning True for ObjectNode, even when schema had explicit `type: "object"`. This caused non-objects to incorrectly pass validation.

**Solution:**
1. Use Pydantic's strict types to prevent coercion:
   - `bool` → `StrictBool` (rejects integers 0/1)
   - `int` → `StrictInt` (rejects bools and strings)
   - `float` → `StrictFloat` (accepts both int and float, rejects strings)
   - `str` → `StrictStr` (rejects non-strings)
   - For constrained strings: `StringConstraints(strict=True, ...)`
2. Fixed `_is_object_only_schema()` to check for explicit `type` keyword in original schema
   - If schema has `type: object`, let Pydantic reject non-objects (correct behavior)
   - If schema only has object keywords without type, use type guard wrapper (filter semantics)

**Code Changes:**
- `python/packages/adapters/pydantic/src/xschema_pydantic/renderer.py`:
  - `render_boolean()`: Returns `StrictBool` instead of `bool`
  - `render_number()`: Uses `StrictInt` for integer, `StrictFloat` for number
  - `render_string()`: Uses `StrictStr` or `StringConstraints(strict=True, ...)`
- `python/packages/adapters/pydantic/src/xschema_pydantic/converter.py`:
  - `_is_object_only_schema()`: Now takes `original_schema` parameter and checks for `type` keyword
- `python/packages/adapters/pydantic/tests/test_renderer.py`:
  - Updated 15 tests to expect strict types

**Testing Results:**
- ✅ type: 100% (80/80 tests passing) across all drafts
- ✅ anyOf: 100% (18/18)
- ✅ const: 100% (54/54)
- ✅ enum: 100% (45/45)
- ✅ multipleOf: 100% (10/10)
- ✅ All 85 pydantic adapter unit tests pass
- ✅ All 79 core package unit tests pass

**Key Insights:**
- JSON Schema's `type` keyword requires strict type validation - no coercion allowed
- Pydantic's union handling with `MultipleOf` has floating point bugs; use `StrictFloat` instead of `StrictInt | StrictFloat` for number type
- `StrictFloat` accepts integers (converts to float) which is fine for validation since integers are numbers
- The distinction between "has type keyword" vs "has type-specific keywords only" is crucial for JSON Schema semantics

## Task: fix-required-validation (COMPLETED)

**Objective:** Fix required keyword validation (was showing 0/16 in latest runs)

**Root Cause:**
- Property names with special characters (newlines, tabs, quotes, backslashes) in `required` array generated invalid Python code
- The previous escaping only handled single quotes: `req_field.replace("'", "\\'")`
- This failed for `foo\nbar` which became a literal newline in the generated string, causing SyntaxError

**Solution:**
- Added two new helper functions in `renderer.py`:
  - `_escape_for_single_quotes(name)`: For use inside single-quoted Python strings (escapes backslashes, control chars, single quotes)
  - `_escape_for_double_quotes(name)`: For use inside double-quoted Python strings (escapes backslashes, control chars, double quotes)
- Both use `json.dumps()` for proper escaping of control characters, then adjust quote escaping based on context

**Code Changes:**
- File: `python/packages/adapters/pydantic/src/xschema_pydantic/renderer.py`
- Added `_escape_for_single_quotes()` and `_escape_for_double_quotes()` helper functions
- Updated required field validation code (lines ~1095-1110) to use proper escaping
- Updated dependency validation code (lines ~1012-1054) to use proper escaping

**Testing Results:**
- ✅ required: 100% (16/16 tests passing)
- ✅ All 85 pydantic adapter unit tests pass
- ✅ All 79 core package unit tests pass

**Key Insights:**
- `json.dumps()` is the right tool for escaping control characters in strings for code generation
- When embedding escaped strings in Python code, must consider the outer quote character
- For single-quoted strings: keep `\"` as `"`, escape `'` as `\'`
- For double-quoted strings: keep `\"` as `\"` (json.dumps output works directly)
