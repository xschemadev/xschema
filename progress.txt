- Bundler uses `Fetcher` interface for external schema resolution - no direct I/O
- `BundleInput` struct groups all bundle parameters (Schema, SourceURI, Fetcher, Draft)

## 2026-01-12 - US-005 & US-006
- Implemented: Nested $defs flattening with recursive extraction and ref rewriting
- Files changed:
  - cli/bundler/bundler.go - Rewrote flattenDefs(), added flattenDefsWithRewrites() and uniqueDefKey()
  - cli/bundler/bundler_test.go - Added 5 new tests for nested defs scenarios
- **Key changes:**
  - flattenDefs now handles BOTH $defs and definitions in the same schema
  - Recursive flattening builds complete rewrite map before applying rewrites
  - Deeply nested refs (e.g., #/$defs/A/$defs/B/$defs/C) now rewrite correctly
  - Key collision handling with __2, __3 suffixes via uniqueDefKey()
- **Tests added:**
  - TestBundle3LevelNestedDefs - 3-level nesting flattens with __ separators
  - TestBundleMixedDefsAndDefinitions - both $defs and definitions flatten
  - TestBundleKeyCollisionWithCounter - duplicate def names get unique keys
  - TestBundleRefsInFlattenedDefsRewritten - internal refs in flattened defs rewritten
  - TestBundleDeeplyNestedRefChain - A→B/$defs/X→C/$defs/Y resolves correctly
- **Learnings:**
  - The rewrite map must be complete BEFORE applying rewrites to defs
  - Nested rewrites need to be "lifted" to parent paths (e.g., #/$defs/B becomes #/$defs/A/$defs/B from outside)

## 2026-01-12 - US-001
- Implemented: Metaschema package for shared fetching, caching, and vocabulary extraction
- Files changed:
  - cli/metaschema/metaschema.go (new) - Created dedicated metaschema package
- **Key functions:**
  - `Get(ctx, uri)` - fetches and caches metaschemas by URI
  - `ExtractVocabulary(schema)` - extracts $vocabulary from metaschema (nil if missing, map if present)
  - `IsStandardDraft(uri)` - detects json-schema.org URLs
  - `ClearCache()` - clears cache for testing
- **Design decisions:**
  - Uses package-level cache with mutex for thread safety
  - HTTPClient is exported var for test mocking
  - ExtractVocabulary returns nil for missing $vocabulary (not empty map) to distinguish "all enabled" vs "none enabled"
- **Learnings:**
  - Bundler already had similar logic in extractMetaschemaVocabulary - this package consolidates it
  - $vocabulary values are booleans indicating if vocabulary is required (not just enabled)
