**xschema** converts JSON Schema into native validators (Zod, Pydantic, etc.) with 98%+ compliance and full type safety.

## The Problem

The JSON Schema ecosystem is fragmented. Every validation library:

- Implements a different subset of features
- Silently fails on complex schemas (refs, circular refs, remote refs)
- Doesn't document which features actually work
- Has poor DX with manual setup and no tooling

You end up writing schemas that "should work" but break at runtime.

## The Solution

xschema solves this by:

1. **Generating native code** - Output real Zod/ArkType/Effect/Valibot schemas, not runtime interpreters
2. **Testing compliance** - Every adapter runs against the official JSON Schema Test Suite
3. **Bundling schemas** - Resolves all `$ref` and normalizes drafts before generation
4. **Providing transparency** - Exactly which features work, which don't, and why

<Callout type="info" title="How it works">
xschema's CLI parses your config, fetches schemas, resolves all references, bundles everything into self-contained units, then calls adapter CLIs to generate native code. Adapters receive "easy" input - no ref resolution needed.

Learn more in [How it works](/docs/internals).
</Callout>

## Quick Example

```jsonc title=".xschema.jsonc"
{
  "$schema": "https://xschema.dev/schemas/typescript.jsonc",
  "schemas": [
    { "id": "User", "adapter": "@xschemadev/zod", "sourceType": "json", 
      "source": { "type": "object", "properties": { "name": { "type": "string" } } } }
  ]
}
```

```bash
bunx xschema generate
```

```typescript title="main.ts"
import { createXSchemaClient } from "@xschemadev/client";
import { schemas } from "./.xschema/xschema.gen.js";

const xschema = createXSchemaClient({ schemas });
const user = xschema("User").parse({ name: "Alice" }); // typed!
```
