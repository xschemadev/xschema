The Valibot adapter converts JSON Schema definitions into [Valibot](https://valibot.dev) validation schemas with full TypeScript type inference.

## Overview

| | |
|---|---|
| **Package** | `@xschemadev/valibot` |
| **Peer Dependency** | `valibot ^0.42.0` |
| **Compliance** | 98.9% |

Valibot is a modular validation library focused on bundle size. xschema's Valibot adapter provides:

- **Near-complete compliance** with JSON Schema specifications (98.9% for draft2020-12)
- **Full type inference** - generated schemas include TypeScript types
- **Tree-shakeable** - only include what you use
- **Minimal bundle size** - modular design keeps bundles small

<Callout type="warn" title="Known Limitation">
Valibot has a bug with properties named `__proto__`, `constructor`, or `toString`. Schemas with these property names will cause runtime errors. This is a Valibot library bug, not an xschema issue. See [Known Limitation](#known-limitation) below.
</Callout>

## Installation

```bash
# Install client and adapter
bun add @xschemadev/client @xschemadev/valibot

# Install peer dependency
bun add valibot
```

```bash
# npm
npm install @xschemadev/client @xschemadev/valibot valibot

# pnpm
pnpm add @xschemadev/client @xschemadev/valibot valibot
```

## Usage

Create a config file (e.g., `user.xschema.jsonc`):

```jsonc
{
  "$schema": "https://xschema.dev/schemas/typescript.jsonc",
  "schemas": [
    {
      "id": "User",
      "sourceType": "json",
      "source": {
        "type": "object",
        "properties": {
          "id": { "type": "string", "format": "uuid" },
          "email": { "type": "string", "format": "email" },
          "name": { "type": "string", "minLength": 1 },
          "age": { "type": "integer", "minimum": 0 }
        },
        "required": ["id", "email", "name"]
      },
      "adapter": "@xschemadev/valibot"
    }
  ]
}
```

Run the generator:

```bash
bunx xschema generate
```

Use the generated schemas:

```typescript
import { createXSchemaClient, XSchemaType } from "@xschemadev/client";
import xschemaManifest from "./.xschema/xschema.gen";
import * as v from "valibot";

// Create client
const xschema = createXSchemaClient(xschemaManifest, {
  defaultNamespace: "user",
});

// Get schema
const UserSchema = xschema("User");

// Validate data with safeParse (returns result object)
const result = v.safeParse(UserSchema, userData);
if (result.success) {
  console.log(result.output); // Fully typed!
} else {
  console.error(result.issues);
}

// Or use parse (throws on error)
const user = v.parse(UserSchema, userData);

// Extract type
type User = XSchemaType<typeof xschemaManifest, "user:User">;
```

## Generated Output

Running `xschema generate` produces:

```typescript
import * as v from "valibot";

export const User = v.object({
  id: v.pipe(v.string(), v.uuid()),
  email: v.pipe(v.string(), v.email()),
  name: v.pipe(v.string(), v.minLength(1)),
  age: v.optional(v.pipe(v.number(), v.integer(), v.minValue(0))),
});

export type User = v.InferOutput<typeof User>;
```

## Supported Features

The Valibot adapter supports most JSON Schema keywords. See the [Compliance](/docs/typescript/adapters/valibot/compliance) page for detailed coverage by JSON Schema draft.

### Highlights

- All primitive types (`string`, `number`, `integer`, `boolean`, `null`, `array`, `object`)
- String formats (`email`, `uuid`, `uri`, `date-time`, etc.)
- Numeric constraints (`minimum`, `maximum`, `multipleOf`, `exclusiveMinimum`, etc.)
- String constraints (`minLength`, `maxLength`, `pattern`)
- Array constraints (`minItems`, `maxItems`, `uniqueItems`, `prefixItems`)
- Object constraints (`required`, `additionalProperties`, `unevaluatedProperties`)
- Composition (`allOf`, `anyOf`, `oneOf`, `not`)
- Conditional (`if`/`then`/`else`)
- References (`$ref`, `$defs`)

## Known Limitation

Valibot has a bug where object properties with prototype-related names cause runtime errors:

- `__proto__`
- `constructor`
- `toString`

When validating an object schema that includes any of these property names, Valibot throws:

```
this.entries[key]._run is not a function
```

**This is a Valibot library bug**, not an xschema issue. The generated code is correct, but Valibot's internal object handling conflicts with JavaScript's prototype chain.

**Workaround**: Avoid using these property names in your JSON Schemas when using the Valibot adapter. If you need to support schemas with these property names, consider using a different adapter like [Zod](/docs/typescript/adapters/zod) or [ArkType](/docs/typescript/adapters/arktype), which have 100% compliance.

## Bundle Size Advantage

Valibot's modular design means generated schemas only include the validators actually used:

```typescript
// Only these functions are included in your bundle
import { object, string, optional, number, pipe, minLength } from "valibot";
```

This makes Valibot an excellent choice for frontend applications where bundle size matters.
