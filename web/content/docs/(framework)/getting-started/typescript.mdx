This guide walks you through setting up xschema in framework mode - the recommended approach for TypeScript projects.

## Prerequisites

- Node.js 18+ or Bun
- A TypeScript project with `"moduleResolution": "bundler"` or `"nodenext"` in tsconfig.json

## Installation

<Steps>
<Step>
### Install the client and your chosen adapter

```bash
# with bun
bun add @xschemadev/client @xschemadev/zod zod

# with npm
npm install @xschemadev/client @xschemadev/zod zod

# with pnpm
pnpm add @xschemadev/client @xschemadev/zod zod
```

The example uses Zod, but you can use any [adapter](/docs/adapters):

| Adapter | Package | Peer Dependency |
|---------|---------|-----------------|
| Zod | `@xschemadev/zod` | `zod@^3.0.0` |
| ArkType | `@xschemadev/arktype` | `arktype@^2.0.0` |
| Effect | `@xschemadev/effect` | `effect@^3.0.0` |
| Valibot | `@xschemadev/valibot` | `valibot@^0.42.0` |

</Step>
<Step>
### Create an xschema config file

Create a file named `user.xschema.jsonc` (the name determines the namespace):

```jsonc title="user.xschema.jsonc"
{
  "$schema": "https://xschema.dev/schemas/typescript.jsonc",
  "schemas": [
    {
      "id": "Profile",
      "sourceType": "file",
      "source": "./profile.schema.json",
      "adapter": "@xschemadev/zod"
    }
  ]
}
```

And create the JSON Schema file:

```json title="profile.schema.json"
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "id": { "type": "string" },
    "name": { "type": "string" },
    "email": { "type": "string", "format": "email" }
  },
  "required": ["id", "email"]
}
```

<Callout>
The `$schema` URL is required - xschema uses it to discover config files. The filename (without extension) becomes the namespace: `user.xschema.jsonc` -> `user` namespace.
</Callout>

</Step>
<Step>
### Run the generator

```bash
# with bunx (auto-detected from bun.lock)
bunx xschema generate

# or with npx
npx xschema generate

# or with pnpm
pnpm exec xschema generate
```

This creates a `.xschema/` directory with generated code:

```
.xschema/
  xschema.gen.ts      # Generated validators and types
  xschema.manifest.json  # Tracks generated files
```

</Step>
<Step>
### Use the generated schemas

```typescript title="app.ts"
import { createXSchemaClient, XSchemaType } from "@xschemadev/client";
import { schemas } from "./.xschema/xschema.gen";

// Create the client
const xschema = createXSchemaClient({
  schemas,
  defaultNamespace: "user",
});

// Look up schemas by "namespace:id" or just "id" with default namespace
const profileSchema = xschema("Profile"); // shorthand for "user:Profile"

// Validate data
const result = profileSchema.safeParse({
  id: "123",
  email: "alice@example.com",
});

if (result.success) {
  console.log("Valid profile:", result.data);
} else {
  console.error("Validation errors:", result.error);
}

// Extract types for use in your app
type Profile = XSchemaType<"user:Profile">;

function createUser(data: Profile): void {
  // data is fully typed
  console.log(data.email);
}
```

</Step>
</Steps>

## What's generated?

The `.xschema/xschema.gen.ts` file contains:

- **Validators**: Native Zod schemas (or ArkType types, Effect schemas, etc.)
- **Types**: TypeScript types inferred from the validators
- **Schema registry**: An object mapping `namespace:id` to validators

Example output for a Zod adapter:

```typescript
// Generated by xschema - DO NOT EDIT
import { z } from "zod"

const user_Profile = z.object({
  id: z.string(),
  name: z.string().optional(),
  email: z.string().email(),
});
type user_ProfileType = z.infer<typeof user_Profile>;

export const schemas = {
  "user:Profile": user_Profile,
} as const;

export type SchemaTypes = {
  "user:Profile": user_ProfileType;
};
```
