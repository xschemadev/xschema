## Basic Usage

Import `convert` from the runtime package and `adapter` from your chosen adapter:

```typescript
import { convert } from "@xschemadev/runtime";
import { adapter } from "@xschemadev/zod";

const results = await convert(
  {
    namespace: "user",
    id: "Profile",
    schema: {
      type: "object",
      properties: {
        id: { type: "string" },
        name: { type: "string" },
        email: { type: "string", format: "email" },
      },
      required: ["id", "email"],
    },
  },
  { adapter },
);

console.log(results[0].schema);
// z.object({ id: z.string(), name: z.string().optional(), email: z.string().email() }).passthrough()

console.log(results[0].type);
// z.infer<typeof user_Profile>

console.log(results[0].imports);
// ['import { z } from "zod"']
```

`convert` returns code strings, not live validators. You get the same output as `xschema generate` but at runtime, ready to write to a file or evaluate.

## Multiple Schemas

Pass an array of `SchemaInput` objects to convert multiple schemas in a single call:

```typescript
import { convert } from "@xschemadev/runtime";
import { adapter } from "@xschemadev/zod";

const results = await convert(
  [
    {
      namespace: "user",
      id: "Profile",
      schema: {
        type: "object",
        properties: {
          id: { type: "string" },
          email: { type: "string", format: "email" },
        },
        required: ["id", "email"],
      },
    },
    {
      namespace: "app",
      id: "Config",
      schema: {
        type: "object",
        properties: {
          theme: { type: "string", enum: ["light", "dark"] },
          debug: { type: "boolean" },
        },
        required: ["theme"],
      },
    },
  ],
  { adapter },
);

// results[0] -> user:Profile
// results[1] -> app:Config
```

## External `$ref` Resolution

If your schemas reference external files or URLs via `$ref`, enable `allowFetch`:

```typescript
import { convert } from "@xschemadev/runtime";
import { adapter } from "@xschemadev/zod";

const results = await convert(
  {
    namespace: "order",
    id: "Order",
    schema: {
      type: "object",
      properties: {
        user: { $ref: "https://api.example.com/schemas/user.json" },
        items: {
          type: "array",
          items: { $ref: "./item.schema.json" },
        },
      },
    },
  },
  { adapter, allowFetch: true },
);
```

<Callout>
Without `allowFetch`, any external `$ref` will cause an error. This is a safety default — enable it only when you trust the schema sources.
</Callout>

## Custom Binary Path

By default, `convert` looks for `xschema` in your `PATH`. To use a specific binary:

```typescript
const results = await convert(schema, {
  adapter,
  executablePath: "./node_modules/.bin/xschema",
});
```

You can also set `cwd` to control the working directory for `$ref` resolution:

```typescript
const results = await convert(schema, {
  adapter,
  cwd: "/path/to/project",
});
```

## Error Handling

When conversion fails, `convert` throws a `ConvertError` with the CLI's stderr output:

```typescript
import { convert, ConvertError } from "@xschemadev/runtime";
import { adapter } from "@xschemadev/zod";

try {
  const results = await convert(schema, { adapter });
  console.log(results);
} catch (error) {
  if (error instanceof ConvertError) {
    console.error("Conversion failed:", error.message);
    console.error("CLI output:", error.stderr);
  }
}
```

Common reasons for errors:
- xschema CLI not installed (install `@xschemadev/cli` or set `executablePath`)
- Invalid JSON Schema
- External `$ref` without `allowFetch: true`
- Adapter package not installed

## What You Get Back

Each item in the results array is a `ConvertResult`:

| Field | Type | Description |
|-------|------|-------------|
| `namespace` | `string` | The namespace you provided |
| `id` | `string` | The schema ID you provided |
| `varName` | `string` | Generated variable name (e.g., `user_Profile`) |
| `imports` | `string[]` | Import statements needed for the generated code |
| `schema` | `string?` | The validator code (e.g., `z.object({...})`) |
| `type` | `string?` | Type expression (e.g., `z.infer<typeof user_Profile>`) |
| `validate` | `string?` | Validation function expression |
| `validationImports` | `string[]?` | Additional imports for the validation function |

<Callout>
`schema` and `type` are optional because some adapters may only generate one or the other. Most adapters (Zod, ArkType, Effect, Valibot) generate both.
</Callout>
